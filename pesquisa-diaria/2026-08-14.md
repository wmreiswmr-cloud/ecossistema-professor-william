## 🎓 Trilha C — Universidade do Innovator Director

### Hoje no currículo
- Fase 2 — UX · tópico do dia: **UX Writing** · progresso: 6/100

### Analisado
- [Nielsen Norman Group, via parallelhq.com — UX Writing Best Practices](https://www.parallelhq.com/blog/ux-writing-best-practices) — nível de fonte: artigo de terceiro citando estudo primário da NN/g
- [Torrey Podmajersky — *Strategic Writing for UX* (resumos convergentes)](https://sobrief.com/books/strategic-writing-for-ux) — nível de fonte: resumo de terceiro (livro em paywall)

### As 10 perguntas
- **Produto:** microcopy resolve o problema de "o usuário não entende o que fazer/o que aconteceu" — reduz erro e abandono.
- **UX:** usuário escaneia (lê só 20-28% das palavras); texto formatado pra escaneamento + linguagem neutra melhora usabilidade em até 124% (estudo NN/g).
- **UI:** n/a — UX Writing é texto, não visual.
- **Motion:** n/a.
- **Engenharia:** provavelmente strings centralizadas (i18n-ready) e revisão de copy como etapa própria do pipeline de release, não texto hardcoded improvisado.
- **Performance:** n/a.
- **Design System:** microcopy deveria ter as mesmas 4 qualidades em todo o produto (purposeful, concise, conversational, clear — Podmajersky) — é um token de "voz", equivalente a paleta/tipografia.
- **Componentes:** mensagem de erro, texto de botão, label de campo, empty state — cada um é um "componente de texto" reaproveitável com regra própria.
- **Lições (melhores ideias):**
  1. Usuário escaneia, não lê — 20-28% das palavras.
  2. Reescrita concisa + neutra: +58% usabilidade; combinada, +124%.
  3. 50% dos erros de usuário vêm de instrução pouco clara.
  4. De quem erra, 79% abandona a página, 27% abandona o site inteiro.
  5. As 4 qualidades de Podmajersky: purposeful, concise, conversational, clear.
- **Aplicação:** o bug real já catalogado do ProfGestor ("Falha no email: ver detalhes" nos contratos assinados, `meta-10k-mensal.md`) é um caso concreto de falha de UX Writing, não só bug técnico — pela estatística da NN/g, tem alta chance de fazer o pai/tutor abandonar a tela sem entender o problema.

### ✅ Registrado na Base de Conhecimento
- `ux-patterns.md` — entrada completa com os 2 achados e a aplicação ao bug real do ProfGestor.
- `universidade-diretor.md` — progresso atualizado (6/100), próximo tópico definido (Onboarding).

### Ritual "1% Melhor Todos os Dias"
- **Maior lição de hoje:** metade dos erros de usuário em qualquer produto vêm de texto pouco claro, não de lógica quebrada — é uma alavanca barata e sub-explorada.
- **Padrão pra memória permanente:** as 4 qualidades de Podmajersky (purposeful/concise/conversational/clear) como critério de revisão de qualquer string nova.
- **Skill/arquivo a atualizar:** `cerebro-editor-in-chief` (revisão de língua) poderia ganhar ponteiro pra `ux-patterns.md` quando revisar microcopy de produto, não só copy de marketing — sugestão, não implementada (fora do escopo desta trilha editar skill).
- **Melhoria aplicável já:** revisar a mensagem de erro real do ProfGestor pelas 4 qualidades — sugestão registrada, depende de acesso ao código.
